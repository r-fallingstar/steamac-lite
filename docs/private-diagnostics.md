# Lite版の任意診断（1.9.8-lite.7以降）

Lite版は、上流のSentryへの送信を作者の非公開GitHubへの報告に置き換える。上流用コードは他のビルドとの互換性のため残るが、LiteではSentry SDKを開始しない。手動の「問題を報告」も専用の送信先を使い、失敗時に上流へフォールバックしない。

## 利用者の選択

初回ウィザードで表示言語・マイク・カメラ・診断情報の送信をまとめて選ぶ。「クラッシュレポートと診断を送信」のチェックは既定でオフ。以前の上流向け設定がオンでも、その同意を新しい送信先へ自動移行しない。診断の解除は「設定 → 一般」で行う。

ウィザードは通常のNSWindowで構成し、入れ子のモーダルループを使わない。表示前にTCCへの権限照会をせず、先に内容を描画する。マイク・カメラは「続ける」を押した後、選んだものが未確認の場合にだけmacOS標準の許可画面を順番に出す。許可の取得処理自体は撮影・録音を開始しない。拒否済みの場合はウィザード内のボタンからmacOSの該当プライバシー設定を開ける。選択と許可結果を従来の起動時確認へ引き継ぎ、続けて同じ案内を重複表示しない。GitHubのDMGとBOOTHネットインストーラーが取得するDMGは同じ本体で、どちらもこのウィザードを使う。

オフはすぐに反映され、ローカルの未送信報告を削除する。有効にした後の起動監視は次回起動から。無効化したセッションは再びオンにしても監視を再開しない。通信開始済みのリクエストや受信済みの報告を後から取り消すことはできない。

手動報告は個別の送信操作を同意として扱い、自動送信の設定とは独立させる。メールは任意。説明、基本的な端末情報、選択したランチャーログの抜粋だけを送る。送るJSON全体を事前に確認でき、SteamOSログ、画面写真、設定ファイルやディスク情報は含めない。

## 検出範囲

小さな`steamac-vm`が先に動き、本体の`steamac-runtime`を起動する。監視のタイマーは本体のspawnより前に、別のキューで動き始める。監視側はlibkrunやSentryをリンクせず、Metalを直接使用しない。初回ウィザードの権限取得にはAppKitとAVFoundationを使う。実行ファイル名とバンドル識別子は旧Lite.9の更新機能と互換に保つ。

- 起動段階や進捗が3分間変わらなければ、`startup-stalled`。
- 起動完了後にメインスレッドの応答が3分間なければ、`app-unresponsive`。
- ランチャーやVMの異常終了、GPUエラー、初期セットアップ失敗などは固定の種類で報告する。VMの異常終了には終了時の起動段階、VMプロセス起動からの経過秒数、終了コードまたはOSから取得したシグナルを含む。アプリ内の強制終了や案内済みの起動拒否は報告対象外。VMがSIGKILLで終了した場合は、カーネルから得られた終了理由をローカルのランチャーログに記録する。
- 監視プロセスごと終了していた場合、次回起動で親子とも存在しないことを確認して`previous-session-incomplete`。強制終了や再起動とネイティブクラッシュを混同せず、原因不明として扱う。

言語選択、インストール確認、ディスク選択、カメラやマイクの許可、終了後の確認画面などで利用者を待っている時間は、起動停止に数えない。スリープやホストの長いスケジューリング停止後には、新たな3分の猶予を設ける。

初回の同意画面より前には自動報告を行わない。Lite.8以降は、ランチャーに到達していれば、設定読み込み・AppKit初期化・初回画面の生成と表示の段階をMac内の統合ログに記録する。[起動時の調査手順](startup-hang-investigation.md#lite8以降で初回画面が出ない場合)から、利用者が停止中に手動で採取できる。

## 自動報告の内容

schema、報告ごとのランダムUUID、固定のイベント種類、アプリ版・ソース識別子、macOS版、Mac型番、チップ、RAM、最後の固定の起動段階、経過秒数、取得できた終了コード・シグナルのみ。

名前、ユーザー名、端末名、Steamアカウント、ゲーム名、画面、ファイル内容、パス、環境変数、ログ全文は自動送信しない。端末を継続識別するIDも作らない。この最初の実装は、ネイティブクラッシュのスタック全文を自動収集するものではない。詳細なスタックが必要なケースは、手動のサンプル採取で補う。

ローカルの自動報告は1日4件、保留10件まで。送信失敗は次回以降に再試行し、7日を過ぎた保留報告は削除する。UUIDを維持して再送するため、受信側は同じ報告を重複登録しない。

## 中継と保存先

```
任意で有効にしたアプリ
  → HTTPSのCloudflare Worker（項目検証・制限）
  → D1の配信待ちキュー（7日保持）
  → 非公開リポジトリのGitHub Actions
  → 非公開Issue
```

保存先は`r-fallingstar/steamac-lite-diagnostics`。アプリと中継サーバーにGitHubのPATは置かない。GitHubへの書き込みは非公開リポジトリのActionsに発行される短期の`GITHUB_TOKEN`を使う。キューを読む認証情報はWorker Secretと暗号化したActions Secretに保管する。

受信APIは不明な項目、自由なファイル添付、不正な型やサイズを拒否する。IPアドレスは一時的な送信量制限にだけ使い、診断レコードやGitHubには保存しない。中継サービスは通信上IPアドレスを受け取る。WorkerのObservabilityログは無効にしている。

GitHubへの反映は1時間ごとのActionsで行う。空の定期実行を減らすためにまとめて同期し、必要な場合は作者が手動でも実行できる。GitHub側で遅れる場合もあり、アプリに出る報告IDは中継側の受信確認を示す。GitHub同期は保存先が非公開であることを毎回確認し、公開に変わっていたら停止する。受信済みのGitHub報告は、作者が管理・削除するまで残る。

## 開発・検証

```sh
python3 scripts/test/lite-diagnostics.py
node --test services/diagnostics/test/*.test.js
python3 services/diagnostics/test/importer_test.py
```

Swiftの実コードで、同意のない送信抑止、同意の移行抑止、3分判定、進捗更新、操作待ち、スリープ猶予、日次制限、キュー削除を検証する。使い捨てのアプリと疑似本体で、ユーティリティのexec、VMとランチャーの終了の識別、報告の重複防止、要求された終了と同意撤回の扱いも検証する。実VMや利用者のディスクは使わない。

サーバー側は許可項目、サイズ制限、認証、受信の重複防止を検証する。GitHub同期は公開リポジトリの拒否、配信失敗時の未確認、再実行時のIssue重複防止を検証する。

`services/diagnostics/deploy.py`は、認証済みWranglerとPyNaClを使って専用サービス・暗号化Secret・非公開リポジトリのワークフローを設定する。秘密値は標準出力に表示しない。送信先は`scripts/lite/diagnostics.json`で管理し、未設定のローカル検証版はDMG配布スクリプトが拒否する。
